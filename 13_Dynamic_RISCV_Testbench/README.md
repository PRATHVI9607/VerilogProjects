# Project 13: Dynamic RISC-V Testbench with Golden Model

## Overview

This project enhances the Pipelined RISC-V CPU from Project 1 with a **dynamic testbench** that automatically verifies any `program.hex` without requiring manual updates to expected values.

## How It Works

```
┌─────────────┐     ┌──────────────────┐     ┌───────────────────┐
│ program.hex │────▶│  Golden Model    │────▶│ expected_values.hex│
└─────────────┘     │  (Python RISC-V  │     └───────────────────┘
                    │   Simulator)     │              │
                    └──────────────────┘              │
                                                      ▼
┌─────────────┐     ┌──────────────────┐     ┌───────────────────┐
│ program.hex │────▶│  Verilog CPU     │────▶│  Actual Results   │
└─────────────┘     │  (DUT)           │     └───────────────────┘
                    └──────────────────┘              │
                                                      ▼
                                              ┌───────────────────┐
                                              │    Compare &      │
                                              │    Report PASS/   │
                                              │    FAIL           │
                                              └───────────────────┘
```

## Key Features

1. **Golden Model** (`golden_model.py`): A Python RISC-V simulator that:
   - Reads `program.hex`
   - Simulates all 24 RV32I instructions
   - Outputs expected register values to `expected_values.hex`

2. **Dynamic Testbench** (`tb/tb_riscv_cpu.v`):
   - Reads expected values from `expected_values.hex`
   - Compares Verilog CPU output against golden model
   - Reports PASS/FAIL for each register automatically

3. **Automated Workflow**:
   - Just run `make sim` - it handles everything!
   - No need to manually update testbench when changing program

## Usage

### Quick Start
```bash
# Just run this - it does everything automatically!
make sim
```

### Step by Step
```bash
# 1. Edit your test program
vim program.hex

# 2. Generate expected values (optional - make sim does this)
make golden

# 3. Run simulation with verification
make sim
```

### Available Commands
| Command | Description |
|---------|-------------|
| `make sim` | Full run: golden model → compile → simulate → verify |
| `make golden` | Generate expected values only |
| `make run` | Quiet run (just PASS/FAIL summary) |
| `make wave` | View waveforms in GTKWave |
| `make check` | Check for Verilog errors/warnings |
| `make clean` | Remove generated files |

## Supported Instructions (24)

The golden model supports all RV32I instructions:

| Type | Instructions |
|------|-------------|
| R-Type | ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU |
| I-Type ALU | ADDI, ANDI, ORI, XORI, SLTI, SLTIU |
| I-Type Shift | SLLI, SRLI, SRAI |
| Load/Store | LW, SW |
| Upper Imm | LUI, AUIPC |
| Branch | BEQ |

## Advantages Over Static Testbench

| Feature | Static (Project 1) | Dynamic (Project 13) |
|---------|-------------------|---------------------|
| Change program.hex | Must update testbench | Just works! |
| Add new test | Manual expected values | Automatic |
| Maintenance | Error-prone | Self-verifying |
| Flexibility | Low | High |

## Requirements

- Icarus Verilog (`iverilog`)
- Python 3.x
- GTKWave (optional, for waveforms)
